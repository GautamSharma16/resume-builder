# System Context & Architecture Guide (For AI Agents)

This document provides a comprehensive overview of the **Cvbliss** application architecture, core workflows, and technical stack. It is designed to give AI coding assistants immediate, high-level context of the repository.

## 🏗️ Architecture & Technology Stack

*   **Backend Framework:** Laravel (PHP 8.2+)
*   **Frontend Stack:** Blade Templates, Tailwind CSS / Custom CSS (Vanilla), Alpine.js / Vanilla JS.
*   **Design System:** Dark theme, Glassmorphism UI, *Bricolage Grotesque* & *DM Serif Display* fonts.
*   **Database:** MySQL / SQLite (Eloquent ORM).
*   **AI Integration:** Google Gemini API (`gemini-flash-latest`, `gemini-pro`).
*   **Payment Gateway:** Razorpay (Webhooks & Payment Links).
*   **PDF Generation:** `barryvdh/laravel-dompdf` (HTML to PDF) and `smalot/pdfparser` (PDF to Text).
*   **Authentication:** Laravel standard Auth + Socialite (Google OAuth).

## 🔄 Core Application Flows

### 1. Resume Building & Improvement Flow
*   **Controllers:** `ResumeBuilderController`, `ResumeController`
*   **Flow:**
    1.  User navigates to `/resume-maker`.
    2.  User fills out dynamic forms for Personal Info, Experience, Education, etc. Data is bound to a JavaScript `state` object.
    3.  Live preview renders the selected template via `TemplateRenderService`.
    4.  User can ask the AI to "Improve" or "Fix Grammar" on specific text fields. The frontend calls `/analyze-resume` or `/grammar-fix-resume`, which triggers `ResumeController` to query the Gemini API.
    5.  User saves the resume (`/resume` POST), storing it in the `resumes` database table as a JSON payload in the `data` column.
    6.  User can download the resume as a PDF via `PdfConversionService`.

### 2. AI Cover Letter Generation Flow
*   **Controllers:** `CoverLetterController`
*   **Flow:**
    1.  User navigates to `/cover-letter`.
    2.  The UI is pre-filled with the user's latest saved resume data or high-quality sample data.
    3.  User uploads an existing resume (PDF/DOCX).
    4.  The backend extracts text and contact info (`extractResumeText`, `extractResumeContact`).
    5.  User provides target Job Role, Company, and Job Description.
    6.  Clicking "Generate" hits `/cover-letter/generate`. The controller prioritizes extracted resume data over manual form data and sends a highly specific prompt to Gemini.
    7.  Gemini returns a tailored cover letter body in JSON format.
    8.  The frontend updates the live template preview instantly.

### 3. Authentication & Authorization Flow
*   **Controllers:** `AuthController`, `GoogleAuthController`
*   **Flow:**
    1.  Unified, glass-morphic UI for Login/Register (`resources/views/auth/login.blade.php`).
    2.  Standard email/password login or Google OAuth via Socialite (`/auth/google`).
    3.  Separate Admin login route (`/admin/login`) sharing the same aesthetic but distinct logic.
    4.  Middleware (`auth`, `admin`, `guest`) strictly protects routes.

### 4. Subscription & Payments Flow (Razorpay)
*   **Controllers:** `SubscriptionController`, `RazorpayWebhookController`, `PricingController`
*   **Flow:**
    1.  User views `/plans` and selects a tier.
    2.  `SubscriptionController` generates a Razorpay Payment Link and redirects the user.
    3.  A pending `Purchase` record is created.
    4.  Upon successful payment, Razorpay hits the `/razorpay/webhook` route.
    5.  `RazorpayWebhookController` verifies the signature, updates the `Purchase` status to `paid`, and uses `PlanActivationService` to grant the user premium access (e.g., unlimited downloads).

### 5. Admin Panel Flow
*   **Controllers:** `Admin\*` (e.g., `DashboardController`, `TransactionController`, `TemplateController`)
*   **Flow:**
    1.  Accessible only via `/admin` prefix to users with the `admin` role.
    2.  **Dashboard:** Views high-level analytics, user growth, and recent transactions.
    3.  **Transactions:** Views all Razorpay payment attempts. Admins can click "Download CSV" which streams a real-time CSV generated by `TransactionController@exportCsv`.
    4.  **Templates:** Admins can activate/deactivate resume and cover letter templates.
    5.  **Articles:** Markdown-based blog management for SEO.

## 📂 Key Design Patterns & File Locations

*   **Logic Heavyweight:** Most external API logic (Gemini, PDF Parsing) is kept inside specific controllers or dedicated services (`app/Services`).
*   **Data Storage:** Resumes and Cover Letters heavily utilize JSON columns (`data` field) in the database to allow flexible schema changes without constant migrations.
*   **Frontend Interactivity:** Heavily relies on Vanilla JavaScript and inline Alpine.js within Blade files. No heavy frontend framework (like React/Vue) is used. State synchronization between form inputs and live template previews is handled via custom JS observers/listeners.
*   **UI Assets:** Global CSS variables are defined in the main layout (`resources/views/layouts/app.blade.php`), ensuring strict adherence to the application's color palette (Navy, Blue, Ink) and typography.
